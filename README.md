# WashingPets System

本仓库包含洗宠机 STM32 APP、Bootloader、上位机通信协议文档和 Linux 工作台工具。

逐个BIN的改动见[APP固件更新日志](CHANGELOG.md)，文件大小、CRC32和SHA256见[固件校验清单](FIRMWARE_MANIFEST.csv)。已整理本地2.3.0~2.3.17共18个版本，缺少逐版记录的历史版本已标注待核实。

## 本次更新内容

### 2026-09-28 清洗末段预热（APP 2.3.17）

- 预热从“清洗计时一开始”改为“清洗剩余60秒”：120秒配方在运行60秒后启动，90秒配方在30秒后启动；非零时长不超过60秒时从开始启动，0秒不预热。
- 使用排除用户暂停时间的流程时钟；恢复时仅恢复已启动的预热，未进入预热窗口不提前加热。保留原清洗结束到烘干的预热交接。
- 本次只改启动时机，预热仍为风机50%、加热棒100%，未增加局部温度或风量检测。之前出现的糊味必须排查，缩短预热不代表已解决过热风险。
- 固件：`WashingPets_App/build/Debug/WashingPets_APP_V2.3.17.bin`。主机回归测试包含启动边界、短配方、零时长、暂停恢复及计时回绕；尚未实机验证。

### 2026-09-28 配方沐浴加液时间（APP 2.3.16）

- 新增每套配方的“沐浴加液时间（秒）”，0~60秒，默认3秒；每轮加液结束后关OUT18和蠕动泵，再按出水时间启动增压泵。设0跳过投液，不产生短暂启动脉冲。
- 循环次数、轮间暂停、末轮不暂停及5秒清水冲管保持不变；暂停恢复及剩余时间统计使用新的配方时间。
- Flash参数V9迁移V4~V8旧配方，全部旧配方加液时间默认3秒，其他设置保留。配方仍为84字节，偏移36改为 `bath_liquid_time_ms`，group=1参数协议版本升为3。
- 两套工作台源码已同步。当前电脑 `/opt/pawclean-workbench/server.py` 的配方部分也已更新，原文件备份为 `server.py.before-bath-liquid-2.3.16`；须升级固件后重启工作台，重新读取配方。
- 固件：`WashingPets_App/build/Debug/WashingPets_APP_V2.3.16.bin`。尚未实机验证实际投液量。

### 2026-09-28 洗护期间并行补水（APP 2.3.15）

- 冲洗、沐浴、清洗阶段（含出水间歇）并行开启OUT7自来水阀和OUT39热水器阀，使用CH4混水温度反馈调比例阀，目标为当前配方 `tank_target_temp_x10`，死区为±1℃。
- 比例阀角度增大表示冷水增多；每5秒最多调3°，死区内保持角度。启动/恢复进水先确认485角度写入成功，正常补水不操作增压泵、淋浴阀或OUT6热水器继电器。
- 高液位连续到位10秒后关闭进水及比例阀；高液位消失后不等待中液位，下一次水箱任务调度恢复补水。GPIO互锁与水箱任务共用输出层计时结果。
- 进入烘干后恢复原来的自清洁冷水备水策略，关闭热水器阀、比例阀90°补冷水，仍受高液位10秒保护。
- 混水补水时CH4无效或超过5秒未更新，关闭进水并按现有安全停机路径上报A4 `0x0309`。暂停、停止、急停及活动故障期间不重新开水。
- 固件：`WashingPets_App/build/Debug/WashingPets_APP_V2.3.15.bin`。闭环响应和高液位后10秒的水箱剩余容量须实机确认，±1℃是调节目标，不保证启动瞬间即可达到。

### 2026-09-28 沐浴循环（APP 2.3.14）

- 每轮先开OUT18和蠕动泵3秒，关闭后再开增压泵，喷水时间及轮间暂停取配方；末轮不暂停，保留末尾5秒清水冲管。
- 沐浴总时间改为循环次数（0~100，默认5），0跳过；蠕动泵与增压泵不同时开启。暂停恢复保持当前阶段剩余计时。
- Flash参数V8自动迁移V4~V7旧配方：旧总时间除以喷水加暂停时间向上取整（最多100轮）。其他设置保留。
- 配方参数块仍为84字节，group=1协议版本升为2；工作台源码同步次数字段，旧版本配方写入被拒绝。已安装的旧工作台需要更新后使用。
- 固件：`WashingPets_App/build/Debug/WashingPets_APP_V2.3.14.bin`。实机投液量、水路效果仍需验证。
- 软件回归测试（gcc、Python3及pyserial）：`python3 -B WashingPets_App/tests/host/run_tests.py`，仅模拟设备，不连接串口。

以下为历史功能汇总，包含已提交和后续调整的功能，不对应某一个BIN的增量；逐版依据以更新日志为准。

### STM32 APP 固件

- 固件切换为真实硬件编译模式：`APP_DRY_RUN_ENABLE=0`。
- 上电默认工作模式改为 `MANUAL` 手动模式；完整自动流程需要上位机先切 `AUTO`，再发送流程启动命令。
- `OUT5` 保持 `PD8 排风紫外线灯`；`OUT29-PF1` 改为增压泵 GPIO 启停，不再使用正门加热功能。
- `OUT26-PC14 舱内照明` 改为低电平有效、上电默认开启，工作台可手动控制；急停/看门狗紧急关断时保持开启。
- 洗前准备流程增加“请求上位机选择本次运行配方”，配方回复数据增加沐浴液选择字段。
- 喷泡沫阶段当前固定使用 `OUT18` 第6路药液阀；上位机沐浴液选择字段仅兼容保留。
- 自清洁流程重做：清洁液喷洒、静置、分路冲洗、消毒液喷洒、冲洗、紫外线消杀与烘干并行。
- 新增快速/深度自检任务 `task_self_test.c/.h`，支持风机、加热、增压泵、阀门、比例阀、热水链路等项目检测，并通过 `0xA7 SELF_TEST_RESULT` 上报结果位图。
- 配方和参数结构升级，新增自检参数组并保留历史参数迁移。
- `0xA4 FAULT_EVENT` 删除 `fault_bitmap`，仅保留 `primary_fault_code`。
- `0xA5 TELEMETRY` 增加 485 执行器状态、流程剩余时间等数据；增压泵改为GPIO后，原压力反馈字段保留为0。
- `0xA6 IO_STATUS` 改为输入/输出位图上报，支持 IO 变化主动上报。
- 增压泵从 485 压力控制改为 `OUT29` GPIO 启停，固件不再轮询站号1、不再上报 `0x0808` 增压泵485通讯失败。
- 比例阀通信健康判断改为按角度写入成功/失败判定，不再使用后台 `0x03` 读反馈寄存器，避免可控制但误报 `0x0809`。
- 21 号四路水温采集模块恢复真实读取；CH3 管路出水口温度因未接入而屏蔽，使用固定管路温度并按有效数据上报。
- 顶部排风扇13号从站当前启用：`RS485_TOP_EXHAUST_PRESENT=1`。

### Bootloader / IAP

- APP 与 Bootloader 的设备 ID 不再使用固定值，统一改为运行时读取 STM32 96 位 UID 并用 CRC32 压缩成 32 位 target ID。
- Bootloader 写 metadata、校验 App、上报设备信息、处理升级开始命令时使用同一套 UID-CRC32 target ID。
- IAP 协议文档同步 target ID 规则和升级交互说明。

### Linux 工作台

- 工作台增加/修正 A4 故障中心详细显示，按 `primary_fault_code` 展示具体故障。
- 修复故障复位后故障显示残留问题。
- 修复 IO 输入/输出状态显示和 A6 位图解析。
