# 自检逻辑流程说明书

> 适用模块：`Core/Src/task_self_test.c` / `Core/Inc/task_self_test.h`
> 运行环境：FreeRTOS（CMSIS-RTOS v2），STM32 主控，RS485 从站通信

---

## 1. 概述

自检（Self Test）是主控对整机执行机构的一次自动化检测流程，用于在正式洗护流程前逐项验证：

- 风机、加热器的 RS485 通信是否正常；
- 加热器是否能真正产生温升（Deep 模式）；
- 注水路径（自来水阀 + 比例阀）是否通畅；
- 各淋浴/自清洁/旁通阀能否建立并保持目标压力；
- 增压泵的加压与压力反馈是否正常；
- 热水回路能否正常注入热水（Deep 模式）。

自检分两种模式：

| 模式 | 枚举值 | 测试项数 | 覆盖内容 |
|------|--------|---------|---------|
| 快速自检 `SELF_TEST_MODE_QUICK` | 0 | 12 | 3 风机 + 3 加热(仅通信) + 注水 + 4 淋浴阀 |
| 深度自检 `SELF_TEST_MODE_DEEP` | 1 | 18 | 3 风机 + 3 加热(测温升) + 注水 + 9 阀 + 热水回路 |

---

## 2. 三个决定判断结果的底层约定

理解自检逻辑前，必须明确以下三点：

### 2.1 输入极性（`AutoDevice_ReadInput`）

- 底层 `ReadInputRaw`：GPIO 为低电平(RESET) → 返回 `1`；高电平(SET) → 返回 `0`。
- 液位/门磁/光幕等信号「触发时」拉低，故 `ReadInput == 1` = 触发。
- 但 `level_reached()` 内部做了取反：`ReadInput == 0 ? 1 : 0`。

**结论**：

| 表达式 | 含义 |
|--------|------|
| `level_reached(TANK_LOW/MIDDLE/HIGH) == 1` | 水位**到达**该液位点 |
| `level_reached(TANK_LOW/MIDDLE/HIGH) == 0` | 水位**未到**（比该点更低） |
| `ReadInput(门关闭) != 0` | 门关闭到位 |
| `ReadInput(光幕) == 0` | 光幕未被遮挡 |

### 2.2 输入是滤波后的稳定值

- 液位类输入：连续稳定 **3 秒** 后才更新；
- 其他输入（门磁、光幕、急停）：去抖 **30ms**。

因此自检读到的水位有约 3s 滞后，这也是所有注水/排水循环采用 20ms 轮询 + 超时兜底的原因。

### 2.3 RS485 通信验证靠「成功计数」

- 每个从站维护一个「成功收发」累计计数器 `TaskComm485_GetStationSuccessCount(station)`。
- 自检判断某从站「真的响应了」的标准：**写命令后，该站 success count 发生变化**，而非仅把命令本地发出。
- 这是所有 `wait_station_write()` 的核心判定依据。

## 3. 运行机制（任务模型）

1. 系统启动时 `TaskSelfTest_Create()` 创建 FreeRTOS 任务 `selfTest`（优先级 `osPriorityBelowNormal`，栈 4KB）。
2. 任务体阻塞在 `osEventFlagsWait` 上等待 `SELF_TEST_EVENT_REQUEST` 事件。
3. 上位机/主控调用 `TaskSelfTest_Request(mode)`：
   - 先执行 `TaskSelfTest_CanStart(mode)` 前置校验；
   - 通过后置 `running = 1`，发送事件唤醒任务；
   - 任务调用 `execute_self_test(mode)` 顺序执行完整流程。
4. 一套自检全程跑在这**一个任务**里，是阻塞式顺序流程，中间用 `osDelay(20ms)` 轮询传感器/通信状态。

### 3.1 全局状态变量

| 变量 | 类型 | 用途 |
|------|------|------|
| `running` | `volatile uint8_t` | 是否正在自检 |
| `paused` | `volatile uint8_t` | 是否暂停 |
| `stop_requested` | `volatile uint8_t` | 是否请求停止 |
| `requested_mode` | `volatile uint8_t` | 请求的自检模式 |
| `current_step_id` | `volatile uint16_t` | 当前步骤号（上位机显示） |
| `progress_x10` | `volatile uint16_t` | 进度（千分制，1000=100%） |
| `tested_bitmap` | `volatile uint32_t` | 已测项目位图 |
| `passed_bitmap` | `volatile uint32_t` | 通过项目位图 |
| `result_pending` | `volatile uint8_t` | 是否有待取结果 |
| `last_result` | `SelfTestResult` | 最近一次结果 |

## 4. 启动前校验 `TaskSelfTest_CanStart`

任一条件不满足 → 返回 0 → 拒绝启动。

| 判断条件 | 含义 |
|---------|------|
| `mode > SELF_TEST_MODE_DEEP` | 模式非法 |
| `running != 0` | 已在自检中 |
| `TaskOutput_IsAutoMode() == 0` | 非自动模式 |
| `AutoProcess_IsRunning()` | 主自动流程正在运行 |
| `TaskClean_IsRunning()` | 自清洁正在运行 |
| `AutoDevice_GetFault() != AUTO_FAULT_NONE` | 系统已有故障 |
| `cabin_is_safe() == 0` | 舱门/急停/光幕不安全 |
| `levels_are_consistent() == 0` | 水位传感器状态矛盾 |
| Deep：`incab_valid == 0` 或水箱温度无效 | 缺少温度传感器 |

### 4.1 `cabin_is_safe()` 判定（全部成立才算安全）

- `IsEmergencyStopped() == 0` → 急停未按下；
- `ReadInput(上门关闭) != 0` → 上门关到位；
- `ReadInput(下门关闭) != 0` → 下门关到位；
- `ReadInput(上光幕) == 0` → 上光幕未遮挡；
- `ReadInput(下光幕) == 0` → 下光幕未遮挡。

### 4.2 `levels_are_consistent()` 判定

- 高液位到达，但中或低未到 → 矛盾（返回 0）；
- 中液位到达，但低未到 → 矛盾（返回 0）；
- 否则正常（返回 1）。

## 5. 主流程 `execute_self_test`

进入后先执行：

1. 清零 `tested_bitmap` / `passed_bitmap` / `completed_items`，设 `total_items`（Quick=12 / Deep=18）。
2. `TaskComm485_ReleaseNonzero(...)` 释放「启动抑制 / 安全停机 / 模式切换 / 暂停」四类抑制。
3. `self_test_outputs_off()` 全输出关断，再释放安全停机抑制。

随后按固定顺序执行各阶段，**任一步返回 `ABORT` 立即 `break` 终止**。

### 5.1 阶段 A：风扇测试 ×3（`test_fan`）

站号：左风机 10、右风机 11、底部风机 12。`current_step_id = 10 + index`。

每台风机：

1. 对应 bit 打入 `tested_bitmap`；
2. `wait_station_write(站号, fast_fan_percent=50%)`：
   - 记当前 success count，`ForceSetPercent` 发 50% 转速；
   - 每 20ms 调 `poll_control` 并检查 success count 是否 +1；
   - count 变化 → `PASS`；超时 3000ms 无响应 → `FAIL`。
3. 无论结果，风机**关回 0%**；`PASS` 则打入 `passed_bitmap`。

> 判定标准：**风机成功应答 = 通信成功**，不检测实际风量。

### 5.2 阶段 B：加热器测试 ×3

站号：左加热棒 14、右加热棒 15、底部加热棒 16。

**快速模式 `test_heater_quick`**（`step_id = 20 + index`）：
- `wait_station_write(站号, 0%)`，仅验证通信可达（写 0% 也会触发应答）。

**深度模式 `test_heater_deep`**（`step_id = 30 + index`）：
1. 三台风机开到 `deep_fan_percent=30%`（通风散热）；
2. 读舱内温度，`incab_valid == 0` → `FAIL`；记录 `baseline`；
3. `wait_station_write(站号, deep_heater_percent=80%)` 出 80% 加热；
4. 观察循环（最长 `heater_observe_ms=45000ms`）每 20ms：
   - 舱温 `>= heater_max_temp_x10=45.0℃` → 报 `OVER_TEMPERATURE` → `ABORT`；
   - 温升 `(当前 - baseline) >= heater_min_rise_x10=0.5℃` → `PASS`；
   - 超时未升温 → `FAIL`。
5. 结束无论成败，加热棒**关回 0%**。

> 判定标准：**Deep 要求温度真的升起来**；Quick 只要求通信应答。

### 5.3 阶段 C：注水路径测试（`fill_to_middle(1)`）

`record_result=1`：作为正式测试项，`step_id = 50`，测 `TEST_BIT_FILL_PATH`。

1. 若水位已到中液位，先 `drain_below_middle()` 排到中液位以下；
2. 关所有水路 → 设比例阀 `proportional_valve_angle=90°` → 开自来水阀 `TAP_WATER_VALVE`；
3. 循环（最长 `fill_timeout_ms=180s`）每 20ms：
   - 水位到中液位 → 关输出 → 记 `FILL_PATH` 通过 → `PASS`；
   - 水位到高液位 → 报 `LEVEL_INVALID` → `ABORT`（过注）；
   - 超时 → `FAIL`。

#### 5.3.1 `drain_below_middle()`（排到中液位以下）

1. 若已低于中液位（`level_reached(MIDDLE)==0`）→ 直接 `PASS`；
2. 关水路 → 只开后淋浴阀 `SHOWER_REAR` 作排水口 → 增压泵加压 `valve_pressure_x10=3.0bar` → 启动泵 `Running=1` + 置压力优先级；
3. 循环（最长 `fill_timeout_ms`）：
   - 中液位消失 → 排够 → 关输出 → `PASS`；
   - **低液位消失** → 排水过头 → 报 `LEVEL_INVALID` → `ABORT`；
   - 全程叠加超压监控 `monitor_pressure_safety`。

### 5.4 阶段 D：阀门 / 增压泵加压测试（`test_valve`）

阀门个数：**Quick 4 个**（淋浴上/中/下/后），**Deep 9 个**（4 淋浴 + 4 自清洁 + 1 旁通）。

每个阀门（`step_id = 60 + index`）：

1. 对应阀 bit 与 `TEST_BIT_BOOSTER` 打入 `tested_bitmap`；
2. 若水位低于低液位，先 `fill_to_middle(0)` 补水（不记测试项）；
3. 关水路 → 开被测阀 → `TaskOutput_Sync(1000)` 确认 GPIO 生效；
4. 增压泵加压 `valve_pressure_x10=3.0bar` → 启动泵 → 置压力优先级；
5. 保压观察循环（最长 `pressure_timeout_ms=10s`）每 20ms：
   - 压力 `> pressure_over_x10=4.0bar` → 停泵 + 报 `OVERPRESSURE` → `ABORT`；
   - 压力进入 `[2.8, 3.2]bar` → 开始计稳定时长，连续稳定 `pressure_stable_ms=2s` → 该阀 + 增压泵 `PASS`；
   - 压力跳出区间 → 稳定计时清零；
   - 低液位消失 → 报 `LEVEL_INVALID` → `ABORT`。
6. `PASS` 后泄压等待 `PRESSURE_RELEASE_MS=1s` 再进入下一个阀。

> 判定标准：**该阀能建立并保持目标压力** = 阀和增压泵都正常。

### 5.5 阶段 E（仅 Deep）：热水路径测试（`test_hot_path`）

`step_id = 100`。

1. `drain_below_middle()` 排空；
2. 读水箱温度，无效 → `FAIL`；记 `last_temperature` 与 `last_update_tick`；
3. 设比例阀到热水注水角 → 开自来水阀 + 热水器阀 `STANDBY2_VALVE`；
4. 观察循环（最长 `hot_observe_ms=60s`）：
   - 水位到高液位 → `FAIL`；
   - 水箱温度采样更新时：连续上升 `trend_count++`，下降则清零；
   - `trend_count >= hot_trend_samples=3`（连续 3 次采样升温）→ `PASS`；
   - 超时 → `FAIL`。

> 判定标准：**热水回路能注入热水、水箱温度连续单调上升**。

## 6. 贯穿全程的安全守卫 `poll_control`

几乎所有循环体内都会调用，优先级从高到低：

| 优先级 | 条件 | 动作 |
|--------|------|------|
| 1 | `stop_requested != 0` | 返回 `ABORT`（手动停止） |
| 2 | `cabin_is_safe() == 0` | 报 `SELF_TEST_NOT_ALLOWED (0x0901)` → `ABORT` |
| 3 | `levels_are_consistent() == 0` | 报 `SELF_TEST_LEVEL_INVALID (0x0904)` → `ABORT` |
| 4 | 舱温 `>= heater_max_temp_x10` | 报 `SELF_TEST_OVER_TEMPERATURE (0x0903)` → `ABORT` |
| 5 | `paused != 0` | 全输出关断，阻塞等待 Resume/Stop；Resume → `RETRY`，Stop → `ABORT` |
| 6 | 全部通过 | 返回 `PASS` |

### 6.1 超压守卫 `monitor_pressure_safety`

仅在排水阶段额外叠加：压力反馈 `> pressure_over_x10=4.0bar` → 停泵 + 报 `OVERPRESSURE (0x0902)` + `ABORT`。

---

## 7. 暂停 / 恢复 / 停止

| 动作 | 立即执行 | 下一轮 `poll_control` 反应 |
|------|---------|--------------------------|
| `TaskSelfTest_Pause` | `paused=1` + 全输出关断 | 阻塞等待 |
| `TaskSelfTest_Resume` | `paused=0` | 返回 `RETRY` → 重跑当前项 |
| `TaskSelfTest_Stop` | `stop_requested=1` + 全输出关断 | 返回 `ABORT` → `break` 收尾 |

`run_with_retry` 采用 `do { action } while(status==RETRY)`，因此恢复后当前步骤**从头重跑**，而非从中间继续。

---

## 8. 收尾与结果上报

1. `self_test_outputs_off()` 全输出关断；
2. 若为 `ABORT`：执行 `AutoDevice_AllDangerousOutputsOff()` + `TaskComm485_RequestSafeStop()` 双重兜底；
3. `publish_result()` 生成结果：`result_id` 自增、填 `mode` / `state`（`COMPLETE` 或 `ABORTED`）、`tested_bitmap` / `passed_bitmap`，置 `result_pending=1`；
4. 上位机轮询 `TaskSelfTest_GetPendingResult()` 取结果，`TaskSelfTest_AcknowledgeResult(id)` 确认后清 pending；
5. 任务复位状态，`AutoProcess_RequestReset()` 请求主流程复位。

## 13. 流程时序总览

```
TaskSelfTest_Request(mode)
   │
   ├─ CanStart 校验 ──失败──► 拒绝启动，返回
   │
   └─ 发事件唤醒任务
        │
        ▼
   execute_self_test(mode)
        │
        ├─ 清零位图/进度，释放抑制，全输出关断
        │
        ├─[阶段A] 3× 风扇       (wait_station_write → 通信应答)
        ├─[阶段B] 3× 加热器     (Quick:通信 / Deep:温升)
        ├─[阶段C] 注水路径      (排水→注水到中液位)
        ├─[阶段D] N× 阀门       (加压→保压稳定)
        ├─[阶段E] 热水路径      (仅Deep，温升趋势)
        │
        │   任一步 ABORT ──────────► break
        │
        ├─ 全输出关断 (+ABORT时危险输出兜底)
        ├─ publish_result(result_id/mode/state/bitmap)
        └─ 复位状态 + AutoProcess_RequestReset
```
